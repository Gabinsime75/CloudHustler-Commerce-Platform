# 05 – ACM Certificate DNS Validation Failure

**Project:** CloudHustler Commerce Platform  
**Phase:** Networking  
**Category:** AWS Certificate Manager (ACM) / Route53 / Terraform  
**Severity:** Medium  
**Status:** Resolved  
**Date:** July 2026

---

# Incident Summary

During the Networking phase of the CloudHustler Commerce Platform deployment, Terraform successfully requested an SSL/TLS certificate from AWS Certificate Manager (ACM), but the deployment stalled while waiting for DNS validation to complete.

Although the certificate request itself succeeded, ACM remained in the **Pending Validation** state because the required DNS validation records were either missing or had not yet propagated.

Since the certificate could not be issued, Terraform was unable to complete the deployment of dependent resources such as the HTTPS Application Load Balancer listener.

---

# Impact

- SSL/TLS certificate was not issued.
- HTTPS listener creation was blocked.
- Secure traffic (HTTPS) could not be enabled.
- Terraform deployment remained incomplete until certificate validation succeeded.

---

# Symptoms

Terraform appeared to hang while creating the ACM certificate validation resource.

Example output:

```text
Still creating...
aws_acm_certificate_validation.certificate:
Still creating... [5m elapsed]
Still creating... [10m elapsed]
```

Within AWS Certificate Manager:

```text
Status:
Pending validation
```

---

# Investigation

The troubleshooting process focused on determining whether the issue originated from Terraform, ACM, or DNS.

---

## 1. Verified Certificate Request

The ACM certificate resource was successfully created.

The requested domains included:

- cloudhusller.com
- www.cloudhusller.com

This confirmed Terraform was communicating correctly with AWS.

---

## 2. Reviewed DNS Validation Records

The validation options generated by ACM were examined.

Each domain required a unique CNAME record similar to:

```text
_acbd123456.cloudhusller.com
```

pointing to

```text
_xxxxxxxxx.acm-validations.aws
```

The investigation confirmed that ACM was waiting for these records to appear in DNS.

---

## 3. Verified Route53 Hosted Zone

The Route53 Hosted Zone was reviewed to ensure:

- Correct hosted zone selected
- Records created in the proper zone
- No duplicate validation records
- Correct TTL values

Terraform was configured to automatically create these records.

---

## 4. Allowed DNS Propagation

Even after the records existed in Route53, ACM still reported **Pending Validation**.

This was determined to be normal DNS propagation delay rather than a deployment failure.

After DNS propagation completed, ACM automatically validated the certificate.

---

# Root Cause

The ACM certificate request was successful, but DNS validation had not yet completed.

Terraform was waiting for ACM to verify the required Route53 validation records before issuing the certificate.

This was a DNS propagation timing issue rather than a Terraform or ACM configuration error.

---

# Resolution

Terraform was allowed to continue waiting while DNS propagated.

Once ACM detected the Route53 validation records:

- Certificate status changed to **Issued**
- Certificate validation resource completed successfully
- HTTPS listener deployment continued automatically

No infrastructure changes were required.

---

# Validation

Deployment success was verified using the following commands.

## Verify Certificate Status

```bash
aws acm list-certificates
```

Expected:

```text
Status: ISSUED
```

---

## Describe Certificate

```bash
aws acm describe-certificate \
  --certificate-arn <certificate-arn>
```

Expected:

```text

```

## Verify Route53 Validation Records

```bash
aws route53 list-resource-record-sets \
  --hosted-zone-id <hosted-zone-id>
```

Expected:

- ACM CNAME validation records exist.
- Record values match those generated by ACM.

---

## Verify HTTPS Listener

```bash
aws elbv2 describe-listeners \
  --load-balancer-arn <alb-arn>
```

Expected:

```text
Port: 443
Protocol: HTTPS
```

---

```bash
terraform state list
```

Expected resources:

```text
module.acm.aws_acm_certificate.this

module.route53.aws_route53_record.validation
```

---

# Lessons Learned

- ACM certificates are not issued immediately after creation.
- DNS validation depends on public DNS propagation, which can take several minutes.
- Terraform may appear stalled while waiting for ACM validation, but this behavior is expected.
- Automatic Route53 validation significantly simplifies ACM certificate management.

---

# Prevention

To reduce similar delays in future deployments:

- Use Route53 for automated DNS validation whenever possible.
- Verify that the hosted zone matches the requested domain.
- Allow adequate time for DNS propagation before assuming deployment failure.
- Validate ACM certificate status before troubleshooting Terraform.

| Area | Result |
|-------|--------|
| Root Cause | DNS validation records had not yet propagated |
| Failure Type | DNS Propagation Delay |
| Terraform Configuration | Correct |
| ACM Configuration | Correct |
| Resolution | Wait for Route53 DNS validation to complete |
| Final Status | Certificate issued successfully |

# Interview Story (STAR Format)

## Situation

While deploying the networking layer of the CloudHustler Commerce Platform, Terraform successfully requested an ACM certificate, but the deployment stalled because the certificate remained in the **Pending Validation** state.

## Task

My objective was to determine whether the issue was caused by Terraform, ACM, or Route53, and complete the certificate deployment without introducing manual configuration changes.

## Action

I verified that Terraform had successfully requested the certificate and reviewed the generated DNS validation records. I confirmed that the Route53 hosted zone contained the required CNAME records and that they matched the validation records generated by ACM. After confirming there were no configuration issues, I monitored the certificate status while DNS propagation completed.

## Result

Once ACM detected the Route53 validation records, the certificate status changed to **Issued**, Terraform completed successfully, and the HTTPS listener for the Application Load Balancer was deployed. The incident reinforced the importance of understanding ACM's asynchronous DNS validation process and avoiding unnecessary troubleshooting while waiting for DNS propagation.
